# 第三阶段（调整版）+ 个人中心 + 正式部署 — 方案

## Context

阶段 1、2、2+ 已经完成（引擎、AI、牌谱回放、近似 GTO 复盘），代码在 `D:\claudecode\card`，`main` 已推送。用户调整了第三阶段的范围，并新增了功能。目标是让家人朋友能在公网上安全地练习，重点放在**牌局分析和技术改进**上：

- 要做：正式账号与安全；钱包、托管、现金局规则补全（不做每日赠送）；单桌 Sit & Go 锦标赛 + 死按钮；牌局可靠性。
- 新增：个人中心（全部历史牌局、每手红黄绿灯、占比统计、趋势曲线）；由用户点击发起的大模型「牌手水平评估」，并对比上一次评估看有没有进步。
- 顺带修掉上一轮暂缓的 23 个小问题。
- 正式部署到 Ubuntu 香港 / 海外服务器。

已确认：
- **筹码来源**：注册时送一笔；用完后用户可以自己补，每次补固定数额，每笔都记账。
- **锦标赛**：单桌坐满即开。
- **管理员**：只能在服务器上用命令创建。

## 总体原则

- 沿用现有架构：单进程；`TableActor` 每桌串行（同步）；`projectView` 是唯一的对外视图；Drizzle + PGlite（开发）/ PostgreSQL（上线）。
- 钱包、数据库这类异步操作放在 `TableRoom` 层先完成，再调用同步的 actor，不破坏 actor 的串行模型。
- 每个里程碑一个分支，先写设计细节和计划，再按测试先行实现；中途做检查点审查，最后整体审查一次，合并到 `main`（与上一轮相同的流程）。

## 建议顺序（按用户价值排；每个里程碑都能单独上线）

| 里程碑 | 内容 | 完成后的价值 |
|---|---|---|
| M1 | 账号与安全 + 管理员 | 可以安全上公网 |

小问题按所属模块分散到各里程碑里修（见文末清单）。M2 之后，每个里程碑完成都按部署手册更新线上环境。

## M1 账号与安全

**数据（`apps/server/src/db/schema.ts` + 新迁移）**
- `players` 扩展为账号表：`username`（唯一；NFC 规范化后转小写比较）、`display_name`（牌桌上显示的名字，即原 nickname）、`password_hash`、`is_admin`、`token_version`、`created_at`。player id 仍是 `p_<uuid>`，牌谱外键不变。
- `invite_codes`：`code`、`created_by`、`expires_at`、`used_by`、`used_at`。一次性使用。

**服务端**
- 新增 `apps/server/src/accounts/`：
  - `register(username, displayName, password, inviteCode)`：在一个事务里核销邀请码并创建用户。
  - `login(username, password)`。
  - `changePassword`。
  - `adminResetPassword`：生成临时密码，`token_version + 1`，让旧登录全部失效。
- 密码哈希用 `@node-rs/argon2`（argon2id，Windows 和 Linux 都有预编译包，不需要编译环境）。
- 用户名 3–20 位，只允许字母、数字、下划线；显示名 1–12 个字（按码点计），NFC 规范化，并去掉零宽、双向控制、C0/C1 控制字符；密码至少 8 位。
- **登录限流**：按 IP 和用户名分别计数，15 分钟内失败 5 次就锁定 15 分钟。用内存计数，单进程足够。
- **JWT** 加上 `ver` 字段，与 `token_version` 比对；`verifyToken` 改为异步查库，WebSocket 握手和 HTTP 接口都校验。
- **接口**：`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/password`、`GET /api/me`。管理员接口：`GET/POST /api/admin/invites`、`POST /api/admin/users/:id/reset-password`、`GET /api/admin/users`。删除 `/api/auth/nickname`。
- **管理员命令** `apps/server/src/cli.ts`：`create-admin <用户名>`（交互式输入密码）、`promote <用户名>`、`invite [数量]`。上线后在容器里执行。
- 统一错误处理：输入错误返回 400，带中文提示；服务端异常返回 500，只返回通用提示，详细内容写日志（修掉"登录时数据库错误把原始信息直接返回 400"的问题）。

**前端**
- 登录 / 注册页（注册要填邀请码）、修改密码、退出。
- `/admin` 页：生成和查看邀请码、用户列表、重置密码（只有管理员能看到）。
- 任何接口返回 401 时统一跳回登录页（修掉复盘时登录过期不跳转的问题）。

**迁移**：开发库里的旧昵称账号没有密码，无法登录（只有测试数据）；线上是全新部署，不需要迁移。

## M2 正式部署（Ubuntu，香港 / 海外）

**代码改动**
- 服务端在生产环境直接托管前端打包产物（`express.static` 加单页应用回退路由），同一个域名、同一个端口提供 HTTP、WebSocket 和静态页面。
- 前端的 `SERVER_URL` 在生产构建里默认用当前域名（`location.origin`），开发时仍用 2567。
- 服务端用 esbuild 打包成单个文件（把 workspace 里的各个 TS 包一起打进去），容器里直接用 `node` 运行，不需要 tsx。
- **优雅关闭**：收到 SIGTERM 后先停止接收新连接，等正在写的牌谱和事件落库，再关闭数据库。修掉"关机不等待未写完的牌谱"。
- `GET /api/health` 返回数据库连通状态，给容器健康检查用。

**部署文件（仓库新增 `deploy/` 目录）**
- `Dockerfile`：多阶段构建（pnpm install → 前端打包 → 服务端打包 → 用 node:24-slim 运行）。
- `docker-compose.yml`：
  - `app`
  - `postgres:16`（数据存在命名卷里，不对外开放端口）
  - `caddy:2`：自动申请 Let's Encrypt 证书，WebSocket 直接透传，配置只有一行 `域名 { reverse_proxy app:2567 }`。
- `.env.example`：`DOMAIN`、`JWT_SECRET`、`POSTGRES_PASSWORD`、`DATABASE_URL`、`LLM_*`、筹码相关数额。
- `deploy/backup.sh` + cron：每天凌晨用 `pg_dump` 压缩备份，保留 14 天；附带恢复命令。
- `deploy/RUNBOOK.md`（中文部署手册）：
  1. 域名 A 记录指向服务器 IP；
  2. 用 ufw 只开放 22、80、443 端口；
  3. 安装 Docker；
  4. 拉取代码，填写 `.env`；
  5. `docker compose up -d --build`；
  6. 在容器里创建管理员、生成邀请码；
  7. 更新流程：`git pull` → `docker compose up -d --build`；
  8. 备份与恢复；
  9. 查看日志、排查故障。
- 登录服务器、填写密钥这些步骤由用户自己操作；手册给出每一条命令。

## M3 自动分析 + 个人中心 + 教练评估

**自动分析（后台）**
- 每手牌保存后，对其中每位真人玩家排队做本地分析。分析放在 `worker_threads` 里跑，修掉"复盘计算占用主线程"的问题。只算本地分析，不调用大模型。
- `hand_analyses` 增加 `good_count`、`ok_count`、`mistake_count`、`ev_loss_bb` 四列，方便统计。新增大模型状态 `idle`，表示"还没请求解说"；原来的认领逻辑把 `idle` 也视为可以认领。
- 本轮修了几处分析算法的问题（见文末），`ENGINE_VERSION` 升到 2，旧的分析在后台重新计算。
- 启动时把还没分析过的牌谱补上。

**个人中心 `#/me`**
- **总览**：按时间范围（7 天 / 30 天 / 全部）统计红黄绿灯的数量和占比；平均每手少赚多少个大盲；按街（翻前 / 翻牌 / 转牌 / 河牌）分开的失误率。
- **趋势图**：按天画红、黄、绿灯占比的折线，叠加失误率，用纯 SVG 画（不引入图表库），手机上也能看；点某一天就筛选那天的牌局。
- **牌局列表**：「一局」指在一张牌桌上连续坐着打的一段，或者一场锦标赛。每局显示时间、牌桌、手数、净输赢、红黄绿数量；展开后是每一手的红黄绿灯；点任意一手进入现有的回放 + 分析页面。
- **接口**：`GET /api/me/stats?range=`、`GET /api/me/trend?range=`、`GET /api/me/sessions?before=`（游标分页，参数格式不对时返回 400，修掉对应小问题）、`GET /api/me/sessions/:id/hands`。

**教练评估（用户点击发起）**
- 新表 `coach_reports`：`id`、`player_id`、`created_at`、覆盖的牌谱范围、`stats` 快照（JSON）、`text`、`status`。
- 点「生成水平评估」时：
  1. 统计上次评估以来的数据：各灯占比、按街和位置的失误、常见漏洞归类；
  2. 漏洞归类由本地规则从各决策点判断，例如"面对下注跟注过宽""该弃不弃""过于被动（建议下注却过牌）""翻前入池过松"等；
  3. 附上上一份评估的统计和文字；
  4. 交给大模型输出：整体水平、3 个最需要改进的地方（每条带具体例子手牌）、和上次相比的变化。
- 新数据少于 30 个决策点时，提示"再多打几手"，不调用大模型。
- 和单手解说共用原子认领和失败重试机制；单独限额，默认每人每天 3 次。
- 发给大模型的只有该用户自己的决策和统计数字，例子手牌只包含他当时能看到的信息，延续现有的隐私规则。
- 页面上可以查看历次评估，并看到两次评估之间的指标变化。

## M4 钱包 / 托管 / 现金局规则 + 牌局可靠性

**复式记账（`apps/server/src/wallet/`）**
- 表：
  - `accounts`：类型分为用户钱包、托管（每桌每人一个 `escrow:<tableId>:<playerId>`）、系统发行、电脑资金、抽水、锦标赛奖池；
  - `ledger_tx`：唯一键 `(kind, ref)`，保证同一笔操作只记一次；
  - `ledger_entries`：每笔交易的所有分录加起来等于 0；
  - 用户账户余额不能为负，由检查约束保证。
- **入座**：`TableRoom` 先把买入额从钱包转进托管（异步事务，带唯一键），成功后才调用 `actor.sit`；如果入座失败就原路退回。
- **每手结算**：一手结束后，按各人净输赢在托管账户之间记一笔，抽水转到抽水账户。这样托管余额始终等于座位上的筹码，随时可以对账。
- **离座、被淘汰、补码**：托管和钱包之间互转。补码只能在两手之间进行。
- **电脑玩家**的筹码从电脑资金账户出、回到电脑资金账户（系统账户允许为负）。
- **自助补码**：钱包余额加上所有托管余额低于门槛（默认 1,000）时，可以点「补充筹码」，每次 +20,000。注册时也送 20,000。数额用环境变量配置。
- 钱包页：余额、流水（入座、离座、补码、锦标赛报名和奖金）。

**现金局规则**
- 买入在 40–100 个大盲之间自选，入座时选择数额。
- 新入座的玩家等到大盲轮到自己才加入，或者选择「立即补一个大盲」。
- 暂离期间错过的盲注记下来，回来时补上。
- 建桌时可选抽水（默认 0%，上限 5%，最多 3 个大盲）。

**引擎改动（`packages/poker-core`，先写测试）**
- `HandStarted` 可以明确指定 `sbSeat`（允许为空，即死小盲）、`bbSeat`、`button`（可以是空座位），以及额外补盲的列表（补盲是死钱，不算本街下注额）。
- 现在由引擎推算盲注位置的逻辑保留，作为默认值。
- `TableActor` 负责计算每手的盲注位置（移动大盲规则），现金局和锦标赛共用。

**牌局可靠性**
- 开局时就写入 `hands` 行（`status = in_progress`）。
- 每个动作按顺序追加到 `hand_events`，通过一个有序写队列写入，失败会重试，写不进去不会卡住牌桌。
- 一手结束时更新为 `complete`，同时写入结果和这手的托管结算交易。
- **启动时恢复**：把所有 `in_progress` 的牌局标记为 `voided`（作废）。作废的牌局没有结算交易，所以每个人的托管余额自然停在上一手结束时的状态，等于这手投入的筹码全部退回；然后把所有托管余额退回各自的钱包；未结束的锦标赛取消并退还报名费。
- 牌谱列表和个人中心只显示 `complete` 的牌局。
- **对账**：管理员命令 `reconcile`，检查每笔交易借贷是否平衡、托管余额是否等于座位筹码。

## M5 Sit & Go 锦标赛 + 死按钮

- **建赛参数**：人数（2–9）、报名费（从钱包扣，进锦标赛奖池账户）、起始筹码（锦标赛筹码，和钱包筹码分开）、盲注结构（预设快速 / 标准 / 慢速，每级的时长、盲注大小、大盲前注）、奖金分配（3 人及以下赢家通吃，4–6 人 65/35，7–9 人 50/30/20）。
- 坐满即开，房主也可以让电脑补满空位后开始。电脑的报名费从电脑资金账户出。
- **引擎**：支持大盲前注（只由大盲一个人支付全桌的前注；是死钱，单独计入底池，按规则参与边池计算），补充对应测试。
- **盲注升级**：到时间后，下一手才使用新级别；牌桌显示当前级别和倒计时。
- **死按钮**：使用 M4 的盲注位置计算。剩 3 人变成 2 人时自动切换单挑规则（按钮位同时是小盲，翻前先行动）。
- 记录每个人被淘汰的顺序，同一手被淘汰的，开局筹码多的名次靠前。最后剩一人时，奖池按名次发到各自钱包。
- 锦标赛没有补码，暂离的玩家照常被收盲注、超时自动行动。
- 个人中心里，一场锦标赛算一局。

## 本轮修复的暂缓小问题（共 23 项）

- **M1**：昵称 / 显示名 NFC 规范化并过滤不可见字符；登录 maxLength 按码点计算；登录时的数据库错误不再返回 400 加原始信息；401 统一跳回登录页。
- **M2**：优雅关闭；建桌时 `botLevel` 和 `botStyle` 严格校验，非法返回 400。
- **M3（分析算法，`ENGINE_VERSION` 升到 2）**：
  - 弃牌率计算排除已全下的对手；
  - 蒙特卡洛全部迭代都发不出牌时，退回到忽略最窄范围再算，而不是返回 0；
  - 重建每条街初始底池时，按短码全下的实际盲注计算；
  - 翻后强度百分位按组合权重计算；
  - 过牌 90% 胜率实现率的设定写入说明；
  - 混合频率的手牌按权重计入范围宽度；
  - 近似平局的阈值改为按底池比例；
  - `getBot('expert')` 返回正确的等级；
  - 模拟脚本 `sim-ai` 支持固定随机种子；
  - 补充多人数、短码、全部风格的 AI 合法性模糊测试。
- **M3（前端）**：
  - 牌谱列表首次加载 / 出错时不再显示"还没有牌谱"；
  - 未配置大模型时分析过的牌，可以补拿解说；
  - 分析条目不再把 div / ul 嵌在按钮里；
  - 无障碍：大厅标签页的 tabpanel、电脑选择框按 Esc 关闭并管理焦点、回放列表标出当前步；
  - 翻前全下的回放，等发到对应街时才显示亮牌；
  - 无效分页游标返回 400。
